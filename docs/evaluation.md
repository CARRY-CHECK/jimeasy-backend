# 평가

질의 구조화, 검색, 판정, 설명을 **단계별로 나눠** 평가했다. 실행 성공(응답이 왔는가)과 정답 일치는 구분한다.
평가셋과 실행 기록은 비공개 말뭉치의 청크 ID를 가리키므로 레포에 없다([data.md](data.md#평가셋-레포에-없음)). 아래 수치는 원래 말뭉치(1,690청크)로 잰 결과다.

## 평가셋

| 항목 | 값 |
|---|---|
| 문항 | 65개 = 기존 50문항(정답 검수본) + 왕복·범위 밖·여행일 15문항 |
| 분류 | 복수 물품, 일반 규정, 조건별(용량·수량·항공사), 국가별, 왕복, 범위 밖, 물품 미명시 등 |
| 정답 물품 / 판정 | 108개 물품, 기내·위탁 판정 216개 |
| 정답 근거 | 근거를 작성한 98개 물품, 정답 청크 쌍 318개(근거 미작성 10개 물품은 검색 평가에서 제외) |
| 구조화 정답 | 문항마다 여행 조건 6필드와 물품명·details의 `expected_parsed` |

모든 정답은 팀이 로컬 청크 본문을 기준으로 작성·검수했다. 외부 웹의 최신 규정과 실제 운항 여부는 검증하지 않았다.

## 지표

`scripts/evaluate_dataset.py`가 저장된 실행 기록(`records/`)만 읽어 채점한다. 평가 중에는 LLM, 임베딩, Chroma를 호출하지 않는다.

| 영역 | 지표 | 계산 단위 |
|---|---|---|
| 구조화 | 조건 필드 정확도, 물품 Precision/Recall, details 정확도(전체·정답이 있는 것만), 질문 전체 일치율 | 문항, 조건 6필드, 정답 물품 |
| 검색 | Recall/Precision/F1/Hit Rate/MRR/mAP@K (ranx) | 질문 × 정답 물품의 macro 평균. 판정에 넘긴 전체 검색 순서(`groups`)를 쓴다 |
| 판정 | Accuracy, Macro-F1(4개 클래스 고정), 클래스별 P/R/F1, 혼동행렬 (scikit-learn) | 물품 × 기내/위탁 |
| 질문 | 질문 전체 판정 일치율 | 물품 누락·추가 없이 모든 판정이 맞은 문항 |
| 설명 | BLEU-4(NLTK), ROUGE-1/2/L | 물품별 `notes`만 비교 |

채점 규칙:

- 물품은 이름(Unicode NFC·대소문자·공백만 정규화)과 사람이 검수한 별칭으로만 연결한다. 순서나 유사도로 추측해 연결하지 않는다.
- 연결되지 않은 정답 물품은 누락 오답, 추가로 나온 물품은 판정 Accuracy 분모에 넣고 오답으로 센다.
- 실행 오류나 기록이 없는 문항도 0점으로 반영한다. 기록에 검색 진단이 있으면 검색만 따로 채점한다.
- `Precision@K`의 분모는 항상 K다. 평가할 항목이 없으면 점수를 0이나 1로 채우지 않고 `null`로 둔다.
- BLEU/ROUGE는 표현 유사도일 뿐 규정·수치·조건의 사실 정확도를 뜻하지 않는다.
- 정답·실행 기록·평가 코드의 SHA-256과 라이브러리 버전을 결과에 남기고, 같은 조건의 실행끼리만 비교한다.

Faithfulness, LLM 기반 Context Precision/Recall 같은 LLM 채점은 쓰지 않았다.

## 결과 1. 검색 후보 (LLM 없이)

정답 구조화에서 만든 검색 쿼리를 넣고, 정답 근거가 후보에 들어오는지만 쟀다. 실제 구조화 오류가 빠진 입력이라 상한에 가깝다.
98개 물품, 정답 청크 쌍 318개. 한 번에 요소 하나씩 바꿨다.

| 설정 | Macro Recall@5 | @10 | @20 | @50 |
|---|---:|---:|---:|---:|
| Dense, 국가 필터 (이전 서비스 방식) | 32.50% | 47.45% | 58.96% | 69.10% |
| Hybrid(BM25+Dense, RRF), 국가 필터 | 31.11% | 45.87% | 56.97% | 73.72% |
| Dense, 국가+항공사 필터 | 37.93% | 51.72% | 63.33% | 75.41% |
| Hybrid, 국가+항공사 필터 | 33.84% | 49.23% | 62.14% | 78.52% |
| Dense, 국가+항공사 필터, 물품명+details 쿼리 | 35.95% | 46.45% | 55.87% | 72.50% |
| Hybrid, 국가+항공사 필터, 물품명+details 쿼리 | 40.26% | 49.86% | 60.10% | 69.66% |

- 깊이를 늘리면 Recall이 오르지만 K=50에서도 정답 쌍의 약 25~30%는 후보 밖이다.
- Hybrid는 얕은 깊이(K≤20)에서 Dense보다 낮고 깊은 깊이(K≥30)에서 높다. 그래서 Hybrid는 재정렬할 후보를 넓게 모으는 용도로 쓴다.
- 항공사 필터는 모든 깊이에서 개선됐다. 쿼리에서 항공사·장소명을 빼면 Dense가 모든 깊이에서 낮아졌다. 항공사명이 해당 항공사 문서를 끌어올리는 신호로 작동한 것으로 보고 전체 쿼리를 유지했다.

## 결과 2. 재정렬 (LLM 없이)

Hybrid + 국가·항공사 필터 후보를 `BAAI/bge-reranker-v2-m3`(fp32)로 다시 매겼다. 입력과 정답은 결과 1과 같다.

| 설정 | Recall@5 | @8 | @10 | MRR |
|---|---:|---:|---:|---:|
| Hybrid 순서 (재정렬 없음) | 33.84% | 45.95% | 49.23% | 0.537 |
| Dense 순서 (재정렬 없음) | 37.93% | 46.67% | 51.72% | 0.618 |
| Hybrid 상위 20 재정렬 | 48.52% | 54.85% | 56.48% | 0.746 |
| **Hybrid 상위 30 재정렬 (채택)** | **50.43%** | **58.10%** | **61.05%** | **0.747** |
| Hybrid 상위 50 재정렬 | 51.24% | 60.44% | 62.59% | 0.754 |
| Dense 상위 20 재정렬 | 50.63% | 57.18% | 58.61% | 0.765 |

- 상위 30개를 재정렬하고 최종 8개를 판정에 넘기는 설정을 채택했다. 50개는 30개보다 Recall@8이 2.34%p 높지만 채점량이 늘어 택하지 않았다. 정답 근거가 5~6개인 물품이 있어 최종 개수는 8로 정했다.
- 실제 서비스 검색 경로(`app.search.retrieve_for_item`)를 같은 입력으로 다시 재면 최종 8개 기준 Macro Recall이 **58.10%**로, 이전 서비스 방식(Dense, 국가 필터)의 41.94%보다 16.2%p 높고 오프라인 재정렬 평가와 같은 값이다.
- 지연(물품 2개 질문, LLM 제외, Mac M1 Pro MPS): 검색+재정렬 8.7초(BM25 캐시 warm)~12.4초(cold). reranker를 CPU에서 돌리면 물품당 수십 초가 걸릴 수 있다.

## 결과 3. 전체 파이프라인 (65문항)

실제 LLM 구조화부터 판정까지 실행한 결과다. 기준선과 현재 버전을 같은 정답·같은 평가 코드로 다시 채점했다(2026-11-02).

| 지표 | 기준선 | 현재 | 변화 |
|---|---:|---:|---:|
| 질의 구조화 전체 일치율 | 43.08% | **90.77%** | +47.69%p |
| 검색 Recall@5 (실제 생성 시 검색 순서) | 28.21% | **48.89%** | +20.68%p |
| 판정 Accuracy | 38.39% (86/224) | **43.58%** (95/218) | +5.19%p |
| 판정 Macro-F1 | 0.3931 | 0.3955 | +0.0024 |
| 기내 / 위탁 Accuracy | 31.25% / 45.54% | 34.86% / 52.29% | +3.61%p / +6.76%p |
| 질문 전체 판정 일치율 | 24.62% | 32.31% | +7.69%p |
| `확인 필요` Recall | 11.43% (4/35) | 5.71% (2/35) | −5.71%p |

| 구성 | 기준선 | 현재 |
|---|---|---|
| LLM | gpt-4o-mini, temperature 0 | 같음 |
| 구조화 프롬프트 | 한국어 ver1(미명시 조건은 null) | 영문 ver2(출발지 한국 기본값, 평가셋과 겹치던 예시 교체) |
| 검색 | Dense, 국가 필터, 최종 5개 | Hybrid → 국가+항공사 필터 → 상위 30 재정렬 → 최종 8개 |

현재 버전의 추가 지표: 구조화 물품 Precision/Recall 99.07%/99.07%, 여행 조건 전체 일치율 95.38%, 명시된 details 정확 일치 83.33%,
검색 Hit Rate@8 91.84%, MRR@8 0.729. 65문항 중 64문항이 정상 응답했고, 1문항은 모델이 입력에 없는 물품 ID를 추가해 검증에서 거부됐다(재시도 없이 오답으로 포함).

해석:

- **구조화와 검색은 크게 좋아졌지만 판정 정확도는 소폭 개선에 그쳤다.** 같은 정답 판정 216개를 직접 대응하면 오답→정답 24개, 정답→오답 15개였다.
- 가장 많은 오류는 `조건부 가능`을 `가능`이나 `불가`로 단정하는 경우다. 조건(용량·수량·포장)이 붙는 규정을 하나의 라벨로 요약하는 기준을 모델과 정답이 다르게 적용했다.
- 정답이 `확인 필요`인 35개 판정 중 33개를 맞히지 못했고, 그중 27개는 다른 라벨로 단정했다(`가능` 14, `불가` 7, `조건부 가능` 6). 정답 근거가 검색됐는데도 다른 일반 자료를 인용해 판정한 사례가 있었다.
- 구조화 점수 차이에는 출발지 기본값 정책 차이도 섞여 있다. 기준선의 "정답 한국·출력 null" 21건은 정책 차이 때문이다.
- 여러 설정을 함께 바꾼 비교이며, 65문항 단일 실행이라 통계적으로 확정된 개선으로 보지 않는다.

## 자동 점수 밖에서 확인한 것

- **범위 밖 질문**: 물품이 없는 질문(여행 일정, 통관·검역 등)은 물품 목록 일치로는 맞지만, 안내 문장이 "범위 밖"을 설명하지 않고 물품을 되묻는 경우가 있었다.
- **왕복 질문**: 가는 편·오는 편 항공사 규정을 섞어 설명하는 경우가 있었다. 편별 카드와 구간 스키마는 구현하지 않았다.
- **오래된 규정**: 개정 전 보조배터리 규정 청크가 검색 결과에 자주 노출됐다. 시행일로 거르는 기능이 없다.

## 직접 실행해 보기 (합성 샘플)

샘플 5문항으로 같은 실행·채점 흐름을 확인할 수 있다. 점수는 실행 확인용이며 위 결과와 비교할 수 없다.

```bash
python -m scripts.run_dataset                      # OpenAI 호출, outputs/runs/attempt_N/에 저장
python -m scripts.evaluate_dataset --run outputs/runs/attempt_1 \
    --query-dataset data/sample/queries.json --k 1 3 5 8
```

검색 실험·재정렬 채점·보고서 도구는 `scripts/evaluation/`과 `app/evaluate_hybrid_search.py`에 있다. 사용법은 [scripts/evaluation/README.md](../scripts/evaluation/README.md)를 보라.
